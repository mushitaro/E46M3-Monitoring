# 実車に繋ぐ — E46 M3 / K+DCAN / DS2

ブラウザから直接ケーブルに話す。**サーバもローカルホストも .NET も要らない**——理由は
`README.md`。デスクトップは Web Serial、Android は WebUSB。

> ⚠ **実車に送るのは読取だけ。** 何を送ってよいかを決めるのは `src/lib/runGate.ts` の
> `mayRun` 一箇所で、実車では読取以外を拒否する。唯一の書込は故障メモリ消去で、確認
> ダイアログを伴う。作動テストと SMG II の試験プログラムは **PRACTICE でのみ**動く。

---

## 0. 要るもの

| | 補足 |
|---|---|
| **K+DCAN ケーブル**（FTDI FT232R 系） | E46 は **K-Line モード**で使う |
| Chromium 系ブラウザ | デスクトップ Chrome/Edge、または **Android の Chrome** |
| Android で使うなら **OTG ケーブル/アダプタ** | 給電できること。§2 を読むこと |
| バッテリ充電器（推奨） | 電圧が落ちるとリンクが切れる。これが最も多い「原因不明の切断」 |
| **https で配信された URL** | WebUSB / Web Serial はセキュアコンテキスト必須。**LAN の IP は該当しない** |

`http://localhost` はセキュアコンテキストとして扱われるので、開発機のブラウザだけは
`npm run dev` で足りる。スマホから開発機の LAN アドレスを叩くと `navigator.usb` が
**黙って存在しない**——ベンチの時間を最も無駄にしやすい落とし穴。

---

## 1. ケーブル（E46）

- OBD-II 16 ピンは**運転席足元**。
- **K-Line は 7 番ピン。** DS2 も KWP もここを通る。
- **E46 に D-CAN は無いので、8 番ピンのジャンパは不要。** 後継車（E9x）向けの手順を
  そのまま持ち込むと、要らない配線を足すことになる。
- 16 番ピンが常時 +12V。**K-Line のプルアップはここから来る**ので、机の上でケーブル単体を
  自己エコーさせることはできない（§5）。
- **イグニッション ON（KL15）**。読取だけならエンジンは停止でよい。

## 2. どちらの経路で繋がるのか

| | デスクトップ | Android |
|---|---|---|
| API | Web Serial | **WebUSB** |
| ドライバ | OS の FTDI VCP | 無し。アプリが FTDI と直接話す |
| ピッカーに出るもの | COM ポート | USB デバイス |

**Android の `navigator.serial` は使えない。** Chrome for Android 138+ は
`'serial' in navigator` を true にするが、列挙するのは Bluetooth の
シリアルポート模倣だけで、**USB の K+DCAN はピッカーに現れない**。両者を区別できる
機能テストは存在しないので、アプリは `transportSelect.ts` で Android を WebUSB に
振り分ける。机上のベンチ機から FTDI 経路を試したいときは `?transport=webusb`。

Android で最初に確かめるのは車ではなく、**この 2 つ**:

1. **OTG が VBUS を出しているか。** 出していなければケーブルの LED すら点かない。
2. **Chrome がインターフェースを claim できるか。** カーネルの `ftdi_sio` が先に
   握っていると claim は失敗する。

どちらも `/usb-check` の **step 2** が車に触る前に答える。ここが通らないうちは、
他のどの手順にも意味がない。

## 3. FTDI の Latency Timer — 通説の訂正

古い手順書（本 repo の旧 `host/CONNECT-VEHICLE.md` を含む）は
「**デバイスマネージャで 1 ms にしろ、怠ると必ず失敗する**」と書いている。
**これは実測に反する。**

- 実車のスイープで **16 ms のほうが 5.7% 速かった**。覚醒回数は 135 → 14。
- FTDI 自身の **AN_107** も 1 ms を勧めていない。**1 は USB のフレーム長そのもの**で、
  そこに合わせるのは待ち時間を無くすのではなく、毎フレーム起こしているだけ。
- そして **WebUSB 経路ではドライバ設定は無関係**。アプリが `setLatencyTimer` で
  自分で設定する（既定 16 ms、データログ走行中だけ 4 ms）。

つまり Android では**設定する場所が無いのが正しい**。デスクトップの Web Serial では
ドライバの値が効くが、既定のままでよい。

## 4. 切り分けの階段

上から順に。**どこで止まったかが、そのまま原因の切り分けになる。**

| # | やること | 通れば分かること |
|---|---|---|
| 1 | **接続**（PRACTICE のチェックを外す） | ポート／デバイスが開けた |
| 2 | **IDENT** — DIAGNOSIS タブのハブ | 配線・7 番ピン・KL15・ボーレートが正しい |
| 3 | **故障メモリ**（同じハブが続けて読む） | SGBD の故障本文が効いている |
| 4 | **ライブ値** — DATALOG タブ | 値と単位が返る。ここまで来れば経路は完全 |

IDENT が返らないときに疑う順序は、**配線 → 7 番ピン → KL15 → モジュールの在否**。
アドレスは `docs/FITMENT.md` の通りで、51 モジュール中いくつかは年式・装備で
そもそも載っていない。

## 5. 机の上で試す（車なしで）

- **PRACTICE モード**は車を必要としない。シミュレータが相手で、作動テストも
  SMG II のウィザードもここでだけ動く。送信経路・武装・STOP・後片付けが、M3 を
  最初の相手にする前に一度は実行される——それがこのモードの存在理由。
- **物理層まで試したいなら、素の FT232R ブレイクアウトで TX–RX をジャンパする。**
  K+DCAN ケーブルでは代用できない: K-Line のプルアップが OBD の 16 番ピンから
  来るので、車に繋がっていないケーブルは自分のエコーを返せない。

## 6. よくある症状

| 症状 | 見るところ |
|---|---|
| ピッカーにデバイスが出ない（Android） | OTG の給電、`/usb-check` step 2、そもそも https か |
| `navigator.usb` が undefined | LAN の IP で開いている。https か `localhost` で開く |
| 接続はできるが IDENT が返らない | 7 番ピン、KL15、モジュールの在否、アドレス |
| 途中で切れる | **電圧**。充電器を繋ぐ。ケーブルの抜けかけも同じ症状 |
| 「電気的な問題」ダイアログが出る | 自分の送信中に K-Line が引き下げられた。再試行では直らない——配線を見る |
| 実行ボタンが無い／灰色 | ゲートが理由を書いている。読取でないか、テレグラムが一意でないか、引数を取るか |

## 参考: アドレス

| モジュール | SGBD | DS2 アドレス |
|---|---|---|
| MSS54（エンジン） | `MSS54DS0.prg` | `0x12` |
| SMG II（変速機） | `SMG2.prg` | `0x32` |
| ABS/ASC MK20（前期） | `ASCMK20.prg` | `0x56` |
| DSC（後期） | `DSC_E46.prg` | `0x56` |

`0x56` は年式で中身が入れ替わる。**同時装着は無い**——`docs/FITMENT.md`。
残り 47 モジュールはアプリのモジュールセレクタに全部出る。アドレスは
`public/ecu-data/index.json` が持っていて、その値は宣言ではなく**実送信の
IDENT テレグラムで裏を取ってある**。

E46 M3 は全て **DS2 / K-Line**。D-CAN・ENET は対象外（後継車用）。
