# 「実車未確認」で止めない

運営者の依頼（2026-11-26）：「多くのモジュールの操作が、車両と確かめてないという理由で止められている。
何度も止めるなと言っているのに止める。なぜか、実車で何を確かめる必要があるのかを明らかにし、二度と
起きない仕様を固めたい」。この文書がその仕様で、`CLAUDE.md` の決まりはここを指す。

## 1. 決まり

1. **「実車未確認」「推定」「未検証」は、出所を言う言葉であって、止める理由ではない。** 画面にも AI の答えにも
   言い添えて、そのまま進める（読む・送る・作る・開ける・取り込む）。「実車で確かめていないので送りません」
   「実車で確かめるまで閉じておきます」は、コードにも文言にも AI の返事にも書かない。
2. **送る直前に止めてよい理由は、§2 の閉じた一覧だけ。** 一覧に無い理由で止める門を足さない。足すときは
   先にこの表に足し、運営者が決める。
3. **実車で確かめることは、アプリが自分で記録する。** 人の手順にしない。答えたバイトは台帳
   （`observed-parked`・`runs`・`verified`）と CO-WORK に残り、それが確認になる。確認が済むまで待たない。
4. **開発の AI（机・自律ループ・開発のセッション）は、「実車で確かめていない」を理由に作業を止めない。**
   作って、模擬（EdiabasLib・PRACTICE の模擬実車・デモテスト）で確かめて、PR にする。実車で確かめることは
   §3 の表の行に足し、作業はそのまま進める。
5. **止まったときは、同じ番で次の手を出す。** 止めた理由・誰が何をすれば進むか・開発でなくせるならその依頼
   （`monitoring_finding` の `ask`、開発なら PR）。理由だけ言って終わらない。

## 2. 止めてよい理由（閉じた一覧）

どれも「その時の車の状態」か「その電文が正しいか」で、実車で過去に確かめたかどうかとは関係しない。

| # | 理由 | 何を守るか | どこ |
|---|---|---|---|
| S1 | 停車が要るものを、送る直前に測った車速が 0 でないとき・測れないとき | 走行中の油圧・変速機・ブレーキの作動 | `session.ts` の `preflightRun`、`vehicleState.ts` |
| S2 | 電圧が 12 V 未満、または SGBD が言うエンジンの状態と違うとき | 作動中の電圧落ち、エンジン停止前提のテスト | 同上 |
| S3 | 部品を動かす・消すものを、読み返して「いいよ」を聞く前 | 何が動くか・何が消えるかを人が知ってから | `assistantMayStart`、画面の確認 |
| S4 | 電文を、そのモジュール自身の SGBD のコードが組めず、EdiabasLib とも一致しないとき | 誰も選んでいないバイトを送らない | `agreedFrame.ts`、`telegramIsCertain` |
| S5 | そのアドレスにいるのが別のモジュールだと IDENT が言ったとき | 別のモジュールの電文を送らない | `variants.ts`、`setSendGuard` |
| S6 | 運営者の表で「出さない」（安全装置の展開・書き込み）、またはキルリストで取り下げたとき | 運営者の決定 | `policy.ts`、`ledger.ts` の `withdrawn` |
| S7 | 一つ動いている間の二つ目 | 一度に一つ | `useActuatorArming` |

止めるのはいつでも誰でもできる（`monitoring_stop_outputs`、画面の STOP、時間切れ）。これは止める側なので一覧の外。

## 3. 実車で確かめること（止めずに、記録で済ませる）

| モジュール | 実車で分かること | 今の扱い | どう確かめるか |
|---|---|---|---|
| MSS54（0x12） | なし（IDENT・故障・ライブ・車速は実車の記録あり） | — | — |
| SMG II（0x32） | 部品が実際に動くか、14 の手順の結果 | 送る。練習の門（§4 D1）が止めている | 実行の台帳（`recordVehicleRun`）とオーナーの言葉（`monitoring_note`） |
| DSC MK60（0x29、線上 0xB8） | 故障コードの読み方（今は ISO 14230 の形として推定）、作動の答えの形 | 送る。「推定」と言い添える | 最初の実車の答えを INPA の表示と見比べ、記録に残す |
| ASC MK20・DSC_E46（0x56） | 運営者の車には居ない（MK60） | 変種が「?」で、動かすものは画面の人の選択待ち（§4 D2） | IDENT が答えなければ「居ない」とする |
| ボディ・快適装備・AV（0x00・0x08・0x44・0x50・0x5B・0x60・0x72・0x7F・0xA4・0xD0・0xE8・0xF0） | 実車では何も要らない。同じアドレスの候補を分ける規則（`D_00xx.grp`）が未変換 | 動かすものは画面の人の選択待ち（§4 D2） | グループファイルの規則を `gen_variants.py` で起こし、EdiabasLib と突き合わせる（開発機で） |
| KOMBI・DSC_E46・ASC・LSZ ほかの故障の読み方 | 故障の場所が INPA と同じか | 読む。「実車未確認」と言い添える | 最初の読取を INPA と見比べる |
| メーターの VIN・走行距離 | 答えの形 | 読む（2026-11-26 に実車で読んだ） | 済 |
| M3 でない E46 の DME・GS20 | 車速の答えが停車で 0、走行で動くこと | 速度源が `usable: false` で、停車が要るものが全部閉じている（§4 D3） | アプリが自分で観測して開ける |
| リンク全体 | K ラインの実効レート、送る直前の測定が実車の値で働くこと | 送る | `REAL-CAR-RUN.md` の手順。記録で済ませる |

## 4. 今のコードとの差（直すもの）

### 運営者が決めるもの

- **D1 練習の門（`OWNER_RULES.practiceFirst`、2026-11-15）。** 今は「この端末で、この項目を PRACTICE で一度動かす」
  まで実車で送らない。AI は PRACTICE に切り替える道具を持たないので、車につないだまま頼まれると必ず「練習から」で
  止まる。運営者の車で止まる理由のいちばん大きいもの（M3 で 564 項目、部品ごと）。
  **案：練習はビルドが済ませる。** CI で全項目を PRACTICE の模擬実車に本物の送信の道（許可・事前の測定・時間切れ・止め）
  で一度ずつ流し、通ったビルドだけを配信する。端末ごと・項目ごとの練習は要らなくなる。ねらい（送信の道が初めて
  走るのが実車にならないこと）は CI が守る。
- **D2 同じアドレスに候補が複数あるモジュール（0x56 を含む 13 アドレス・M3 の 30 モジュール）。** 今は画面で人が一度選ぶまで
  動かすものを送らない（AI は選べない）。**案：グループファイルの規則で IDENT が選ぶ**（0x12・0x32・0x80 と同じ。
  実車は要らない）。規則ができるまでの間は、オーナーが声で言った車の装備を AI が記録できるようにし（画面の選択と
  同じ所に残す）、IDENT が答えないアドレスは「居ない」とする。
- **D3 M3 でない E46 の速度源。** 今は人が実車で確かめて `usable` を書き換えるまで閉じている。**案：アプリが自分で
  開ける。** その車で、停車中（回転がアイドル、DME かメーターの両方が読めるならその両方）に 0、走行中に 0 でない値を
  一度ずつ観測したら、その車の速度源として台帳に記録して使う。運営者の車（M3）には関係しない。

### 古い文言（決まりが変わったのに残っているもの）

人にも AI にも「確かめていないものは断る」と言っている。§1 の 1 に合わせて直す。

- 免責事項（`src/lib/i18n/ja.ts`・`en.ts` の `disclaimer_points`、`DisclaimerDialog.test.ts`）：「実車に送るのは読取だけ」
  「確認が取れていない操作は、理由を示して拒否します」「作動テストを試せるのは PRACTICE だけ」。2026-11-14・15 の決定より古い。
- `gate_practiceOnly`（「未検証のため実行できません。実車で 1 件ずつ検証し台帳に記録してから解禁します」）：
  SERVICE の止めのボタン（`src/app/page.tsx`）と DSC の油圧の止め（`src/components/DscHydraulics.tsx`）が、押せない
  ボタンにこの文を出している。
- `run_block_notVerified`（`runGate.ts` の型と i18n）：どこからも返らない理由。消す。
- SERVICE の各行の「実車未確認」：送れるかとは関係しない（`ServicePane.tsx` の `VerifiedBadge`）が、全行に出て止めの
  札に見える。実車で動かした回数があるときだけ出す形にする。
- `ledger.ts` の冒頭（「書き込みの道は無い」）、`public/guide/faults.md` の「MK60 は PROBE の手順にまだ入れられない」
  （実行器は MK60 の故障読取を持つ）。

### 検査

- 文言の検査：画面と AI の答えの文に、止める理由として「未確認」「未検証」「not verified」「not confirmed on a car」が
  出ないこと（出所の言い添えは可）。
- `RunBlockKey` の各値が §2 のどれかに当たることを、型の表で固定する。

## 5. なぜ止まり続けたか

- 運営者の「止めるな」は会話の中にしかなく、`CLAUDE.md`・Skill・guide・記憶のどこにも書かれていなかった。新しい
  セッションは毎回コードと文書から慎重さを読み直し、「実車未確認」「実車まで閉じている」「人が確かめてから」
  （`speedSources.ts`・`FITMENT.md`・`ENGINE.md`・`ledger.ts` の注釈）を止める決まりとして読んだ。
- 画面の文言（免責事項・`gate_practiceOnly`）が、廃止した「読取だけ」の決まりを言い続けていた。
- 実際の門（練習・変種・非 M3 の速度源）は実車の確認ではなく別のものを見ていたが、断る文と AI の言い換えが
  「実車で確かめていない」になっていた。
