# 画面の設計 — UX-01〜33 を直すときの決まり（2026-11-21）

`UX-PROPOSALS.md` の 33 案を、画面ごとにばらばらに直さないための設計。拠りどころは `tsunagi-m-design`（六つの原則・§1.5 状態・§4 プリミティブ・§7 ハブ）と `tsunagi-m-ux`（§6 確認・§16 PRACTICE・§17 言葉の置き場所）。
新しい決まりを作るのではなく、規則がすでに言っていることに画面を揃える。足すより先に、消す・まとめる・奥へ・揃える。

運営者の決まり（何を車に送るか、いつ、誰が始めるか、確認で何を押させるか）はここで変えない。

## 1. 一画面に、主操作は一つ。それは輪にある

- 輪（ハブ）は、その画面でいま押す一つの操作。押せない飾りの輪（`LINKED`）を出さない。
  | 画面 | 輪 |
  |---|---|
  | DIAGNOSIS | READ（全モジュールなら SCAN） |
  | DATALOG | RECORD／記録中は STOP |
  | PROBE | START／走っている間は STOP |
  | ACTUATOR・SERVICE・ADAPTATION | 選んだ行の RUN（何も選んでいないときは無効で「行を選ぶ」） |
  | STARTUP | NEXT |
  | MEMORY | SAVE |
- **作動中・手順中は、どの画面でも輪が STOP**（`armed-danger`、赤、脈なし）。行の中の STOP は消す。止める入口は一つ。
- ほかの操作はサブアクション（2 つまで、溢れさせない）。それ以上は画面の中へ。

## 2. 言葉の置き場所は三つだけ

| 置き場所 | 中身 | 長さ |
|---|---|---|
| 通知行（ハブの上、14px の予約） | 押した結果と、できない理由だけ。MAIN にある文は出さない | 結論を先に、切れても意味が残る長さ（全角 24 字ほど）。全文は `title` と COMMS LOG |
| `Section` の `note` | 区画について変わる事実の一行（「85 件中 12 件を動かせます」）。全行に共通の札はここに一度 | 一行 |
| `Section` の `info`（ⓘ） | 説明。押したときだけ開く | 段落可 |

- 行・カード・ダイアログの本文に説明の段落を置かない。
- 同じことを同じ画面で二度言わない（見出しと札、札と説明、MAIN と通知、MAIN と VISU）。
- **残り秒は通知行に一度**（「油圧ポンプ · 残り 8 秒」）。行は札だけ。

## 3. 名前の位置には人の名前だけ

- 主スロット（行の名前、カードの題、グラフの凡例、判定・比較の行、計画の文、ダイアログの題）は `HumanName` だけ。
- 識別子（`19:v`、`smg2:STATUS_IO_LESEN:…`、`J1`、ジョブ名、SGBD の独語の値、生の 16 進）は、`ident` スロットか ⓘ・詳細の奥。
- 日本語の名前が無いときは、主スロットに英独の原文や機械訳の混ざった語を出さない。独語が残っていなくても、辞書の語を機械が並べただけの訳（`許可15`）は人の書いた名前ではない（訳の出所 `tier`、`src/lib/faultText.ts` の `untranslatedText`）。分類の日本語（「SMG の値」「故障 2F43」のように、出所の確かな語）を主に置き、原文は `ident` に置く。推し量った訳を本物の顔で出さない。
- 一つのものに一つの語。モジュールは日本語名で全画面同じ（「ラジオ」。`Radio` と混ぜない）。

## 4. 状態の札は一つの部品、語は一組

`Pill` 一つで、語と色は次の表だけ（§1.5：定常の事実でない状態は色以外も持つ）。

| 語 | 色 | 動き |
|---|---|---|
| 作動中・手順中・読取中・記録中 | 菫 | 脈打つ |
| 接続待ち・待っている | 菫 | 脈打つ |
| 断った・故障 n・失敗 | 赤 | 定常 |
| 取った・完了・故障なし | 灰（中立） | 定常 |
| 止めた・時間切れで止めた | 灰 | 定常 |

- 「故障なし」「応答あり」を太い青で叫ばない。青は押せるもの・選んだもの。
- 同期の語は一組：「この端末だけ」「送る待ち」「送った」「送れない（理由）」。送り先の無いビルドを赤（失敗）にしない。

## 5. 確認ダイアログは一つの形

`tsunagi-m-design` §4 のモーダルの家族。

- **題は動くもの・消えるものの名前**（「油圧ポンプ」）。
- **本文は 3 段**。
  1. 何が起きるか（「油圧ポンプが回ります」）
  2. いつまで（止まる条件：「10 秒で止まります。STOP でいつでも」）
  3. 押すと（「RUN で送ります」）
- **アプリが測る前提は、測った値で出す**（運営者、2026-11-21）。電圧 12 V 以上・停車・SGBD が言うエンジンの状態は、送る直前にリンクが測り、合わなければ送らない（`preflightRun`）。だから印は押させず、最後に測った値を一行で出す（「電圧 12.6 V（前回の測定）」「停車中（0 km/h、前回の測定）」）。この 1 分に測っていなければ「押すと測ってから送ります」。最後の測定が合わないときは、その行を赤で、どうすれば動くかと一緒に出す。その測定がいまのもの（エンジンの言う「今を言える」5 秒以内。記録中ならそう）なら RUN／START は押せない。それより古ければ、人がもう直したかもしれないので押せるままにし、「押すと測り直してから送ります」と添える。どちらでも、決めるのは押したときの測定。どれが測る前提かは、ダイアログを開いた判定（許可を出すのと同じもの）から決める（`lib/gateChecks` の `measuredAtSend`）。GateDialog と手順の最初の段で同じ（手順の SGBD の文のうち、電池の文は測るので印を外し、充電器の助言は残す）。ADAPTATION の行は前提を文で並べるだけで印が無いので、そのまま。AI が始めるとき（`monitoring_actuate`・`monitoring_procedure`）は、オーナーの「いいよ」が読み返した前提への答えで、同じ関門と同じ送る直前の測定を通る。
- **測れない前提はチェックボックスのまま**（手順の「ニュートラル」「油温が常温付近・平坦な場所」など、測れないものが混じる文）。戻せないこと・止められないことの確認もチェックボックスのまま。
- 人への安全の指示（触れる／触れない、エンジンをかける／止める）は、印を外しても本文に見えるまま残す。
- SGBD の引用・送る電文・ジョブ名は「詳細」（ⓘ）の奥。本文と詳細が食い違わない。
- 注意のうち、人に何かをする・しないを言う文（「実行中はブレーキペダルに触れないでください」、エンジンを止める／かける、ハンドルから手を離す）は詳細ではなく前提の一部。読み手の言語で本文に出す（`lib/instructions`）。印は増やさない（押させるのは、測れない前提と、戻せない・止められないことの確認だけ）。注意の全文は詳細に残す。GateDialog・手順の「何が起きるか」・ADAPTATION の行で同じ。
- 答え：抜け道は素で先、進む道は塗りで後（破壊は赤塗り）。
- 結果の段は抜け道（CLOSE、素）一つ。結果の良し悪しで答えの色を変えない。
- 故障の消去の確認も同じ形（題「エンジン（MSS54）の故障 3 件」→ 消えるもの → 戻せない → 押すと）。

## 6. 走行中の画面は、一目で読める数だけ

- DATALOG・PROBE の VISU は、パネル 4 枚まで。目標と実測は一枚（題一つ、凡例は「目標」「実」）。名前は切らない。残りは「ほか n 項目は LIST」と一行。
- 同じ値を MAIN と VISU に二度出さない。VISU はグラフ、MAIN は数の列。
- PROBE を止めたあとも、最後の回をボードに残す（空にして説明文を出さない）。

## 7. 揃えるだけのもの

- タブの能動は一つ（青の文字と下線）。
- グラフのカーソルは中立（slate）。赤は故障と危険だけ。
- PRACTICE のチェックボックスは、ハブ右上に常設（接続中は減光）。練習の車の設定（ENGINE）は PRACTICE の奥。
- 右列の見出しは `VISU`。
- ヘッダの同一性は人の読める名（車種・モジュール名・版）。IDENT の生バイトと LEN は COMMS LOG へ。
- サブアクション行は 2 つまで。ナビ幅で溢れない。
- 予約スロット（通知行・サブアクション行）は空でも高さを保つ。

## 8. 確かめ方

- 機能：シナリオ 52 本（U1〜U8）が合格のまま。文言を変えたら、合格基準の意図（オーナーに見える・聞こえる）を弱めずにシナリオを直す。
- 見え方：合格した回の撮影を、コードを見ない別のレビュアーが D1〜D3 で判じ直す（`DESIGN-REVIEW.md` と同じ方法）。前回の × と △ の数と並べる。
