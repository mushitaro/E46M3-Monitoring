# 仮想車両での画面操作テスト — 項目

目的：仮想車両で通ったものは、実車でも同じ操作で同じように動く、と言えるところまで試す。
2026-11-19 の実車で、AI が SMG II のアクチュエータ駆動を「一度だけ」（pulse）で頼んだら、値の組が一つも返らなかった。
デモテストはその呼び方を通っていなかった。だから、**見本を一つ選んで試すのをやめ、全部の項目を、全部の入口と呼び方で試す**。

## 0. 原則

1. **数え上げる。** 項目は手で選ばない。動かす項目は `runCoverage` の一覧（E46 M3 567、M3 以外の E46 243）から、
   読む項目は各モジュールのジョブ表から、AI の道具は `tools.ts` の 36 個から作る。一覧が増えれば、試験も増える。
2. **入口ごと、呼び方ごと。** 同じ項目を、次の全部で通す。
   - 画面：ACTUATOR の RUN または START、SERVICE、ADAPTATION
   - AI：`monitoring_actuate` の pulse と start、値あり・値なし、`monitoring_procedure`、`monitoring_stage`
3. **線の上を見る。** 「started: true」で合格にしない。仮想車両が受け取ったバイト列を記録し、次の三つが EdiabasLib の電文と
   一致することを確かめる。
   - 送った順番
   - 宛先
   - 止めの電文（時間切れのときも）
4. **実車の振る舞いを練習の車に持たせる。** 実車でしか起きないことは、次の三つで出す。
   - 否定応答
   - 無応答
   - 状態の変化（車速・電圧・エンジン）
   条件を変えるのはシナリオで、正常の答えは EdiabasLib の模擬で返す。
5. **断る道も試す。** 断るべきときに断り、正しい理由を言うこと。誤った理由（今回の「組が無い」）は不合格。

## A. 仮想車両 — いまある練習の車と、足りないもの

仮想車両は新しく作らない。PRACTICE の練習の車（`packages/monitoring-engine/src/practiceCar.ts`・`practiceEcu.ts`）
を使う。デモテストはテスト用ビルドの口（`src/lib/e2e.ts` の `car.get / set / reset`）から、この車の状態を変える。

**もうあるもの**

| 何を | どこで |
|---|---|
| 後期 E46 M3（SMG II・DSC・ナビ）と、M3 以外の E46（MS43・GS20）の IDENT | `M3_IDENTS`・`NON_M3_IDENTS`、`idents` |
| 載っているモジュール。載っていないものは答えない | `fitted` |
| 車速・エンジンの回転・電圧 | `speedKmh`・`engineRunning`・`batteryV` |
| 故障メモリ。DME・各モジュール・DSC MK60（KWP）・MS43。消去の電文で実際に消える | `dmeFaults`・`moduleFaults`・`dscMk60`・`ms43Faults` |
| メーターの VIN の下 7 桁 | `clusterVin` |
| 線ごと落とす | `lineDown` |
| ナビの時計（サーバーの時刻を聞く） | e2e の `clock.hear` |
| 動かすジョブの答え。EdiabasLib の模擬が返したもの | `setPracticeAnswers`（`job-frames.oracle.json`） |

**足すもの（この 3 つが無いと、E の表が実車の保証にならない）**

| # | 足すもの | なぜ |
|---|---|---|
| A1 | 車が受け取ったバイト列の記録を、試験から読めるようにする | 「始まった」ではなく、送った順・宛先・止めの電文を EdiabasLib と比べるため（原則 3） |
| A2 | 電文ごとに、否定応答（0xB0 など）・無応答・短い答え・遅い答えを返させる | `lineDown` は線ごとしか落とせない。実車の「その電文だけ断る」を出すため |
| A3 | 0x56 を前期（ASC MK20）に切り替える | いまは後期（DSC）だけ。前期の車で別の SGBD を選ぶことを確かめるため |

## C. 読む

全モジュール × 全部の読取ジョブで、次を回す。

| # | 操作 | 合格 |
|---|---|---|
| C1 | DIAGNOSIS で故障を読む。故障の無いときと、入れたとき | 項目がそのモジュール自身のジョブの文で出る。生のバイトだけで終わるモジュールが 0 |
| C2 | MSS54 の故障 | 専用の解読器で、場所・種類・フリーズフレーム |
| C3 | 非 M3 の DME と GS20 の故障 | fault-layouts で読み、「実車未確認」と表示する |
| C4 | DSC MK60 の故障を走行中に | KWP で読める |
| C5 | IDENT と状態の値の読取を、全部のジョブで | ジョブの文の結果が出る。読めないものは「分からない」と出る（推定を実測の顔で出さない） |
| C6 | `monitoring_faults`・`monitoring_scan`（全モジュール） | 画面と同じ結果。VIN は返さない |
| C7 | 走行中の読取 | 走行中も可のもの（識別・故障・状態の値）は読む。台帳で許されていない読取は送らない |
| C8 | 車速が読めないとき | 走行中とみなす |

## E. 動かす（全項目）— 一番大事な表

`runCoverage` の「動く」全項目（M3 567 ＋ 非 M3 243）について、項目ごとに次の行を全部回す。
値を取るジョブは、少なくとも次の値で回す。

- 一致した組の全部の「部品」（第 1 引数の値ごとに 1 組）
- 数の範囲の両端と、途中の値

| # | 入口・呼び方 | 合格 |
|---|---|---|
| E1 | 練習モードで、画面の ACTUATOR（RUN／START） | 確認のあと、記録された電文が EdiabasLib と一致する。台帳に `practiced` が付く |
| E2 | 練習モードで、AI `monitoring_actuate`、phase pulse | 同上（入れて止める形のジョブは止めを置いて始める） |
| E3 | 練習モードで、AI `monitoring_actuate`、phase start | 同上。STOP と `monitoring_stop_outputs` で止めの電文が出る |
| E4 | 値を取るジョブを AI が値なしで呼ぶ | 選べる組が返る。0 組のときは本当の理由を言う |
| E5 | 一致していない値・範囲外の数・知らない語を渡す | 始めない。理由は「その組は比べていない」 |
| E6 | 入れたまま放っておく | ジョブの時間切れ（無ければ 10 秒）で止めの電文が出る |
| E7 | 一つ入れたまま、別のものを始める | 断る（一度に一つ） |
| E8 | 2 通以上送るジョブ | 許可した順の電文だけが出る。途中で否定応答が来たら止める |
| E9 | 実車モードに切り替えて、練習済みの項目を停車中に | 送る直前に車速・電圧・エンジンの状態を測ってから送る。台帳に実車の実行が残る |
| E10 | 実車モードで、練習していない項目 | 断る。理由は「練習から」 |
| E11 | 実車モードで、走行中・電圧 11 V・エンジンの状態が SGBD の言うものと違う | それぞれ断る。正しい理由を言う |
| E12 | 運営者の表で「画面の人」の項目を AI が呼ぶ | 断る。`monitoring_stage` で画面に置ける |
| E13 | 書き込み・安全装置の展開 | どの入口でも出さない |
| E14 | 「外の理由で動かない」148 件 | 画面と AI に、その理由がそのまま出る |
| E15 | DSC MK60 の作動・油圧・調整・動作モード | KWP の電文で E1〜E11 の全部 |

## I. AI の道具（36 個、全部）

道具ごとに、次の四つを回す。

- 正常
- 断られる条件
- タブが閉じているとき
- 走行中

| 道具 | 主に見ること |
|---|---|
| status・guide | 画面と一致、ガイドが新しい版 |
| catalog・ledger | 動かせるかと、その本当の理由。値の組の数 |
| faults・scan | C と同じ |
| module・connect・disconnect・display・show | 画面が本当に変わる |
| actuate・stop_outputs・stage・procedure | E と F の全部 |
| start_log・stop_log・log_channels・datalog・moment | D と同じ |
| save・sync_upload・sessions・session・compare | D と同じ |
| investigate・plan・finding・note・mark・cowork・run_overview・probe | H と同じ |
| open_tuner | TUNER に切り替わる |
| dev_request・dev_status | タブが無くても中継から届く |

## K. 合格の決め方

- E の表は、項目数 × 入口の数だけ行がある。1 行でも落ちれば配信しない。
- 落ちた行は、項目・入口・送った電文・期待した電文・返した理由を報告に並べる。
- 仮想車両で試せないもの（次の三つ）は、試験が「実車でだけ確かめる」と明記して数える。
  - 本物のモジュールが EdiabasLib の模擬と違う答えを返すこと
  - 部品が本当に動くこと（音・圧・動き）
  - ケーブルとナビの USB の電気的な振る舞い
