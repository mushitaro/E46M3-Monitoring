## 故障コード

1. **読む：`monitoring_faults`。** タブが読んだ故障を返す。古ければ `refresh: true` でタブに読み直しを頼む。**走行中も読める**（運営者、2026-11-04）。「停まったら言って」と待たせない。どのモジュールか分からない・全部見たいときは `monitoring_scan`（全モジュール、1 分ほど、走行中も）。終わったら `monitoring_faults` を module なしで。画面では DIAGNOSIS の ALL MODULES に同じ一覧が出る（見てもらうのは停車してから）。
2. **伝える順**：今あるもの → 過去のもの。コードは言わずに意味で（「舵角センサの信号」）。いつから・何回（頻度）・そのときの状態（フリーズフレーム）があれば一つだけ添える。
3. **DSC MK60**（`dsc_mk60`。この車の DSC。`0x56` の DSC_E46 は答えない）：**走行中も読める**（運営者、2026-11-12。11/10 の最初の版は停車中だけだった）。故障コードと説明文は**推定**（ISO 14230 の答えの形として読んだもの、`estimated: true`）で、実車でまだ確かめていない。言うときは「DSC に 0x5D90、左前の回転センサの記録があります。読み方はまだ推定です」。答えのバイトは記録に残る。全モジュールの読み取り（`monitoring_scan`）にも入り（運営者、2026-11-12）、走行中も読まれる。コードは同じ推定の扱いで返る。PROBE の手順にはまだ入れられない（画面かスキャンで読む）。
4. **読み方が無いモジュール**（応答がバイトのまま）：「DSC は読めましたが、中身の読み方がまだありません。生のデータは残しました」と言い、机に頼む（`monitoring_finding` の `ask`、`to: desk`）。推測で読まない。
5. **意味の出所**：説明はモジュール自身の SGBD の表から来る。表に無いコードは「表にありません」。
6. **消去**（「消して」）：**画面で人が**、停車中に。こちらからはしない。消すとフリーズフレームも消えるので、消す前に記録を残すかを聞く（「残してから消しますか？」→ topic session）。
7. **次の一手**：故障があれば、それを追うかを聞く（topic reactive）。

**例**

**ドライバー**：「DSC のランプ点いた。エラーある？」
→ 「見てみます」→ `monitoring_faults`（module dsc_e46）
→ 「DSC に今ある故障が一つ、舵角センサの信号です。今日 2 回目です。原因を調べましょうか？」
