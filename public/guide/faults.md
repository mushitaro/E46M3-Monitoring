## 故障コード

1. **読む：`monitoring_faults`。** タブが読んだ故障を返す。古ければ `refresh: true` でタブに読み直しを頼む。**走行中も読める**（運営者、2026-11-04）。「停まったら言って」と待たせない。どのモジュールか分からない・全部見たいときは `monitoring_scan`（全モジュール、1 分ほど、走行中も）。終わったら `monitoring_faults` を module なしで。画面では DIAGNOSIS の ALL MODULES に同じ一覧が出る（見てもらうのは停車してから）。
2. **伝える順**：今あるもの → 過去のもの。コードは言わずに意味で（「舵角センサの信号」）。いつから・何回（頻度）・そのときの状態（フリーズフレーム）があれば一つだけ添える。
3. **どのモジュールを読み、故障を何で読むか**は `monitoring_capabilities` の `modules`（`faults`・`chosenBy`）と、道具の答えが言う。ここには書かない。答えに `estimated: true` があれば（DSC MK60 を最後まで読めなかったとき）、「DSC に 0x5D90、左前の回転センサの記録があります。読み方はまだ推定です」と添える。答えのバイトは記録に残る。
4. **答えの読み方は答えの欄が言う**：`decoded`（専用の解読器）、`sgbdRead`（そのモジュール自身の SGBD の故障読取のコード。`complete: false` は途中で止まった）、`unverified`（SGBD が読む場所から）。どれでもないときだけバイトのまま（`note` がそう言う）で、そのときは「〇〇は読めましたが、中身の読み方がまだありません。生のデータは残しました」と言い、机に頼む（`monitoring_finding` の `ask`、`to: desk`）。推測で読まない。
5. **意味の出所**：説明はモジュール自身の SGBD の表から来る。表に無いコードは「表にありません」。
6. **消去**（「消して」）：停車中に。消すとフリーズフレームも消えるので、消す前に記録を残すかを聞き（「残してから消しますか？」→ topic session）、何が消えるかを読み返して「いいよ」のあとで `monitoring_actuate`（そのモジュールの消去のジョブ。topic service）。
7. **次の一手**：故障があれば、それを追うかを聞く（topic reactive）。

**例**

**ドライバー**：「DSC のランプ点いた。エラーある？」
→ 「見てみます」→ `monitoring_faults`（module dsc_mk60）
→ 「DSC に今ある故障が一つ、舵角センサの信号です。今日 2 回目です。原因を調べましょうか？」
